## Sammanfattning

P3.0b Del 1 + Del 2 + Del 3 levererade på en arbetsdag (~3h aktiv tid över tre passes). Path A (xmlbuilder2 + arkityp-specifik OPT-byggare) som tidigare ansågs hög-risk producerade välformad OPT-XML som EHRbase 2.30.1 accepterar med **HTTP 201 på iteration 1** — den `COMPOSITION-omslutning kring EVALUATION`-risk som triggade v2 Path C-pivot materialiserade sig inte tack vare att Path C-OPT:en användes som structural reference.

Tio compositions producerade i `medication_summary.v1` end-to-end (Warfarin × 5, Metoprolol × 3, Apixaban × 1) — alla via composer HTTP-route → EHRbase → AQL-fråga returnerar drug + dose.

En arkitektur-bug (B13: dubbel composition per event) upptäcktes och fixades i Del 3.

## Kända begränsningar

### B13 — dubbel composition per event (åtgärdad i Del 3)

HTTP-route skapade outbox-rad med status='pending' och POSTade synkront. Outbox-processor pollade 'pending' i parallel-loop. Race-fönstret mellan write och mark-completed gjorde att processor:n tog upp samma rad och POSTade en ANDRA composition. Fix: HTTP-source skapas direkt som 'processing' (processor plockar bara 'pending'). `recoverFromCrash` vid composer-startup hanterar hängande 'processing'-rader.

### B14 (ny, ej introducerad av P3.0b) — KRaft Kafka topic-partition-resolution

Composer's och fhir-facade:s KafkaJS-konsumenter får `KafkaJSProtocolError: This server does not host this topic-partition` vid subscribe. Producern (kafka-test-producer) lyckas producera utan problem — det är specifikt consumer-coordinator-protokollet som failar. Composer hanterar det gracefully ("continues without Kafka"); fhir-facade kraschar (level 50 fatal).

Föreslagen åtgärd för B14:
- Verifiera Kafka KRaft controller är fully bootstrapped innan konsumenter startar (depends_on med condition kanske inte tillräcklig)
- Eventuellt byta från KRaft till Zookeeper-mode tillfälligt
- Eller fixa fhir-facade så materializer-failure är non-fatal (matcha composer-mönstret)

### ATC + route i 'local'-terminology

EHRbase 2.30.1 har en NPE i ItemValidator när DV_CODED_TEXT använder en terminology som inte är registrerad (Δ rubric-lookup → null → NPE). Workaround: bind till `local`-terminology som EHRbase accepterar opakt. Kodvärdena (B01AA03, PO osv) bevaras i `code_string` så framtida terminology-bindning är trivial.

### Kafka-audit ej live-verifierad

`BRIDGE_*`-events emitteras korrekt i koden och har enhetstester (AC-F8/F9 i bridge-test-sviten). Live-verifiering mot Kafka-topic `core.audit.access` skedde inte pga B14.

### `EXPECTED_TEMPLATES` updaterad i `docker-compose.yml`

`medication_summary.v1` är nu i listan. Composer loggar "all expected templates present" vid startup.
